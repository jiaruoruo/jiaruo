## 二、核心概念（必考）

### 1. 故障链三要素
- **Fault（故障）**：异常状态，可能导致元素失效
- **Error（错误）**：计算/观测值与正确值之间的偏差
- **Failure（失效）**：元素因故障表现而无法执行预期功能

> 链条：Fault → Error → Failure → Malfunction → Hazard

### 2. 功能安全定义
**Functional Safety** = 因电气/电子系统 malfunction 导致的危险引起的**不合理风险的消除**

### 3. Item 定义
应用 ISO 26262 安全开发生命周期的**最高层级对象**，即车辆层面实现某功能的系统（或系统组合）。

## 三、ASIL 分级（高频考点）

### ASIL 等级判定 — HARA 三个维度

| 维度 | 等级 | 说明 |
|------|------|------|
| **S（严重度）** | 0-4 | 0=无伤 / 1=轻伤 / 2=重伤 / 3=致命伤 / 4=群死群伤 |
| **E（可控性）** | 1-2 | 1=可控 / 2=不可控 |
| **E（暴露频率）** | 1-10 | E1-E10，从极罕见到极频繁 |

### ASIL 分类结果
| ASIL | 含义 | 要求严格度 |
|------|------|-----------|
| **QM** | 质量管理 | 最低，按常规质量流程 |
| **ASIL A** | 汽车安全完整性等级 A | 基础功能安全要求 |
| **ASIL B** | 汽车安全完整性等级 B | 中等 |
| **ASIL C** | 汽车安全完整性等级 C | 较高 |
| **ASIL D** | 汽车安全完整性等级 D | **最高**，最严格 |

> ⚠️ **ASIL 分解**：ASIL D 可分解为 ASIL C + QM、ASIL B + ASIL B 等，但需论证独立性

## 四、HARA 分析流程（Part 3 核心）

```
车辆功能识别 → 场景定义 → 危害分析 → 风险评估(S×E×E) → ASIL 分配 → 安全目标
```

**关键输出**：
1. 车辆功能和安全相关场景
2. 危害列表
3. ASIL 评级结果
4. **安全目标（Safety Goals）**

## 六、安全机制设计要点

| 机制类型 | 示例 | 适用场景 |
|----------|------|----------|
| **冗余** | 锁步核、双核、传感器冗余 | 检测硬件失效 |
| **监控** | 看门狗、内存保护、电压监控 | 运行时监控 |
| **降级** | 限扭矩、退出自动驾驶、安全状态 | 失效后处理 |
| **诊断** | BIST、在线测试、CRC校验 | 检测和隔离故障 |

## 七、ASIL 分析方法（Part 9）

| 方法 | 用途 | 特点 |
|------|------|------|
| **FTA（故障树分析）** | 顶事件→底事件，自顶向下 | 分析系统级失效原因 |
| **FTA-FMEA** | 结合 FTA 和 FMEA | 识别单点和潜伏故障 |
| **FMEDA** | 失效模式效应及诊断分析 | 计算随机硬件失效指标 |
| **Dependability Tree** | Part 9 新方法 | 依赖树分析，替代传统方法 |

## 九、常见考题类型

1. **选择题**：概念辨析（故障 vs 错误 vs 失效）
2. **场景题**：给定场景做 HARA 分析，判断 ASIL 等级
3. **流程题**：安全开发生命周期各阶段输入/输出
4. **计算题**：PMHF、SPF、LatF 指标计算（硬件）
5. **论述题**：安全机制设计思路、ASIL 分解论证
6. **案例分析**：给定事故场景，分析功能安全流程缺失
