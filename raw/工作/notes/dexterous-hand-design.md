## 1. 概述

### 1.1 灵巧手技术指标

| 指标 | 目标值 |
|------|--------|
| 自由度 (DOF) | 14-20（手指 4×3 + 拇指 4，含 wrist 可选） |
| 关节控制周期 | 1kHz（位置环）/ 10kHz（电流环 FOC） |
| 通信接口 | EtherCAT / CAN-FD（与大脑节点） |
| 传感器 | 编码器（14bit）、力矩传感器、IMU（6轴）、触觉阵列 |
| 供电 | 24V DC（与机器人平台统一） |
| 延迟 | 手端端到端 < 2ms |

### 1.2 与现有机器人平台的关系

```

│              大脑 (Throux + STM32)          │
│         高层规划 · 决策 · 感知融合          │

     ┌─────────┼─────────┐
     │         │         │
  ┌──▼──┐  ┌──▼──┐  ┌──▼──────────┐

## 2. 处理器选型

### 2.1 需求分析

灵巧手控制器的计算负载分为三层：

| 层级 | 任务 | 周期 | 算力需求 |
|------|------|------|----------|
| **硬实时** | FOC 电流环（每个关节） | 100μs | 浮点运算密集型 |
| **软实时** | 位置/速度 PID、阻抗控制 | 1ms | 中等 |
| **应用层** | 手势识别、力控策略、通信 | 5-20ms | 内存/带宽密集型 |

**核心挑战**：
- 14-20 个关节 × 3 环控制 = **大量并行 FOC 运算**
- 传感器融合（编码器 + 力矩 + IMU + 触觉）= **高频 ADC 采集**
- 触觉阵列数据量大 = **DMA + 大内存需求**
- 与大脑节点同步通信 = **低延迟总线接口**

### 2.2 候选方案对比

#### 方案 A：STM32H7 单核（推荐用于低 DOF 场景）

| 项目 | 参数 |
|------|------|
| 芯片 | STM32H743 / STM32H753 |
| 内核 | Cortex-M7, 480MHz, FPU, DSP |
| Flash | 2MB / 4MB |
| SRAM | 1MB / 1.2MB (含 CCM 512KB) |
| FOC 能力 | 支持 6-8 路独立 FOC |
| ADC | 3×12bit, 2.4MSPS, 同步采样 |
| 总线 | ETH(IEEE 1588), CAN-FD×2, SPI×6, UART×6 |
| ETHERCAT | 软件栈（SOEM）或配合 FPGA |
| 成本 | ¥40-60 |
| 供货 | ST 官方，稳定 |

**优点**：生态成熟、开发工具完善、与现有项目一致
**缺点**：高 DOF 场景 FOC 算力不足

#### 方案 B：STM32H7 + 分布式 FOC 协处理器（⭐ 推荐方案）

| 项目 | 参数 |
|------|------|
| 主控 | STM32H743（运动规划 + 通信 + 传感器融合） |
| 协处理器 | STM32G474 × N（每片负责 2-3 关节 FOC） |
| 协处理器内核 | Cortex-M4, 170MHz, FPU, DSP |
| 协处理器 FOC | 内置 3 相 FOC PWM + 硬件计算单元 |
| 主协通信 | SPI（高速，20MHz+）或 FSMC |
| 成本 | 主控 ¥40 + 协处理器 × N × ¥20 |
| 14 DOF 示例 | 1×H743 + 5×G474 ≈ ¥140 |

**优点**：
- FOC 负载分散，每片 G474 专注 2-3 关节
- H7 专注高层算法，不抢占硬实时资源
- G474 专为电机控制设计，硬件 FOC 单元
- 模块化扩展 — DOF 增加只需加协处理器

**缺点**：
- PCB 复杂度增加
- 主协同步需精心设计

#### 方案 C：RISC-V 高性能 SoC

| 项目 | 参数 |
|------|------|
| 芯片 | 沁恒 CH32V307 / 乐鑫 ESP32-C6 |
| 内核 | RISC-V, 280MHz |
| 成本 | ¥10-20 |

**优点**：成本低、国产可控
**缺点**：生态不成熟、FOC 支持弱、与现有平台不一致

#### 方案 D：Xilinx Zynq FPGA + ARM（高 DOF 场景）

| 项目 | 参数 |
|------|------|
| 芯片 | Zynq-7000 / MPSoC |
| ARM | Cortex-A9 / Cortex-R5 |
| FPGA | 并行 FOC + EtherCAT 硬件加速 |
| 成本 | ¥200-500 |

**优点**：FPGA 可并行处理所有关节 FOC、EtherCAT 硬件级
**缺点**：成本高、开发门槛高、功耗大

### 2.3 推荐方案：方案 B（主控 + 分布式协处理器）

```
最终选型：
┌─────────────────────────────────────────────┐
│  主控：STM32H743VIQ (Cortex-M7, 480MHz)      │
│  - 2MB Flash, 1MB SRAM + 512KB CCM          │
│  - 运动规划、阻抗控制、传感器融合             │

## 3. 操作系统设计

### 3.1 选型对比

| 特性 | FreeRTOS | RT-Thread | Zephyr | 裸机 |
|------|----------|-----------|--------|------|
| 内核大小 | 3-5KB | 8-12KB | 15-30KB | 0 |
| 实时性 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| STM32 支持 | 原生 | 原生 | 原生 | - |
| 组件生态 | 基础 | 丰富（Sensor、Net） | 极丰富 | 无 |
| 国产生态 | 一般 | 强（沁恒/华大等） | 一般 | - |
| 多核支持 | SMP 实验性 | SMP | 好 | - |
| 学习曲线 | 低 | 低 | 中 | 低 |
| 许可证 | MIT | Apache 2.0 | Apache 2.0 | - |

### 3.2 推荐方案：FreeRTOS（主控）+ 裸机状态机（协处理器）

**主控 (STM32H743) — FreeRTOS**
- 原因：高层算法需要任务调度、消息队列、事件组
- 配置：configMAX_PRIORITIES=10, tick=100Hz

**协处理器 (STM32G474) — 裸机 + 状态机**
- 原因：FOC 电流环 100μs 太紧，RTOS 调度开销不可接受
- 方案：中断驱动 + 状态机（参考 ST 的 FOC 参考代码）
- 优势：确定性延迟、零调度开销

### 3.3 主控 FreeRTOS 任务设计

```
优先级映射（数值越大优先级越高）：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 Pri 9  │ EtherCAT 从站任务      │ 1ms 时基 │ 硬实时
 Pri 8  │ 传感器采集任务         │ 1ms 时基 │ 硬实时
 Pri 7  │ 运动规划任务           │ 1ms 时基 │ 软实时
 Pri 6  │ 阻抗控制任务           │ 2ms 时基 │ 软实时
 Pri 5  │ 力控策略任务           │ 5ms 时基 │ 应用
 Pri 4  │ 手势识别任务           │ 10ms 时基│ 应用
 Pri 3  │ 触觉处理任务           │ 20ms 时基│ 应用
 Pri 2  │ 通信管理任务           │ 事件驱动 │ 应用
 Pri 1  │ 系统监控/日志          │ 100ms    │ 后台
 Pri 0  │ Idle                   │          │
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### 任务详情

**1. EtherCAT 从站任务 (Pri 9, Stack 2KB)**
```c
// 时基：1ms (SysTick 中断触发)
// 功能：
//   - 接收 PDO（大脑下发的目标位姿/力矩）
//   - 发送 PDO（关节状态/传感器数据）
//   - 状态机管理（INIT → PREOP → SAFEOP → OP）
// 实现：SOEM 协议栈，ETH 中断 + 轮询
// 关键：保证 1ms 内完成，否则丢周期
```

**2. 传感器采集任务 (Pri 8, Stack 2KB)**
```c
// 时基：1ms
// 功能：
//   - 从各协处理器 SPI 读取关节数据（角度/力矩/温度）
//   - IMU 数据读取（I2C, 200Hz）
//   - 触觉阵列数据（I2C/SPI, 50Hz）
//   - 数据预处理：滤波、校准、单位换算
// 输出：sensor_fusion_buffer[]
// DMA：SPI 传输使用 DMA，CPU 仅处理完成中断
```

**3. 运动规划任务 (Pri 7, Stack 4KB)**
```c
// 时基：1ms
// 功能：
//   - 接收目标手势/位姿（来自大脑或自主策略）
//   - 逆运动学求解（IKE）：目标 → 关节角度
//   - 轨迹生成：五次多项式 / S型速度曲线
//   - 关节限位检查（软硬限位）
// 输出：joint_target[]（目标角度/速度/加速度）
// 算法：Jacobian 伪逆 / CCD-IKE
```

**4. 阻抗控制任务 (Pri 6, Stack 2KB)**
```c
// 时基：2ms
// 功能：
//   - 阻抗/导纳控制：F = M(dq-dq_d) + B(q-q_d) + K(q-q_d)
//   - 接触力自适应
//   - 碰撞检测（力突变检测）
// 输出：joint_torque_override[]
// 安全：碰撞检测 → 紧急力矩限制
```

**5. 力控策略任务 (Pri 5, Stack 2KB)**
```c
// 时基：5ms
// 功能：
//   - 握力自适应（根据物体硬度调节）
//   - 防滑策略（力-位混合控制）
//   - 抓取策略库（精密抓、力量抓、钩挂抓）
// 输入：触觉 + 力矩传感器
// 输出：grasp_force_profile[]
```

**6. 手势识别任务 (Pri 4, Stack 8KB)**
```c
// 时基：10ms
// 功能：
//   - 手势模式库匹配（捏、握、抓、指、拳）
//   - 来自大脑的高层指令解析
//   - 自主手势决策（可选，需 AI 模型）
// 输出：gesture_mode → 运动规划
// 可选：TinyML（TensorFlow Lite Micro）
```

**7. 触觉处理任务 (Pri 3, Stack 4KB)**
```c
// 时基：20ms
// 功能：
//   - 触觉阵列数据解析
//   - 滑移检测（防滑控制输入）
//   - 纹理/硬度分类
// 输入：指尖触觉传感器（每个指尖 4-16 点）
```

**8. 通信管理任务 (Pri 2, Stack 2KB)**
```c
// 事件驱动
// 功能：
//   - CAN-FD 配置/诊断消息
//   - 参数在线更新
//   - 错误日志上传
```

**9. 系统监控任务 (Pri 1, Stack 1KB)**
```c
// 时基：100ms
// 功能：
//   - 温度监控（芯片 + 关节电机）
//   - 电压/电流监控
//   - 内存使用统计
//   - 任务执行时间统计
//   - 故障计数/记录
// 输出：health_status → 大脑节点
```

### 3.4 IPC 机制

```
任务间通信：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
EtherCAT ──queue──> 运动规划 ──queue──> 阻抗控制
                                      │
传感器采集 ──queue──> 阻抗控制 <──────┘
                                      │
                              力控策略 ──queue──> 协处理器
                              （SPI 批量下发）
                              
共享数据：
- joint_state_t[]    — 传感器 → 运动规划（mutex 保护）
- sensor_fusion_t    — 传感器 → 力控（信号量保护）
- grasp_config_t     — 力控 → 协处理器（DMA 传输）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 3.5 协处理器裸机架构

```
STM32G474 程序结构（每个协处理器独立运行）：

中断层（硬实时，不可抢占）：
  TIM1_UPDATE  ──> FOC_SVPWM_Update()    // 10kHz, 100μs
  ADC1Converted ──> Current_Sample()     // 10kHz, 注入采样
  TIM8_UPDATE  ──> Encoder_Read()        // 10kHz

主循环（软实时）：
  while(1):
    PID_Position()       // 位置环 PID
    PID_Velocity()       // 速度环 PID  
    Limit_Check()        // 限幅（角度/速度/力矩/温度）
    SPI_Transmit()       // 向主控上报状态
    SPI_Receive()        // 从主控接收目标值
    Fault_Check()        // 故障检测（过流/过温/通讯丢失）
```

### 4.2 启动流程

```
上电
 │
 ├─ 协处理器启动
 │   ├─ 时钟初始化 (170MHz)
 │   ├─ PWM/ADC/TIM 配置
 │   ├─ FOC 参数加载
 │   └─ SPI 就绪 → 等待主控指令
 │
 └─ 主控启动
     ├─ 时钟初始化 (480MHz)
     ├─ FreeRTOS 初始化
     ├─ EtherCAT 初始化 → 状态 INIT
     ├─ 扫描协处理器 (SPI 握手)
     ├─ 加载关节参数/校准数据
     ├─ EtherCAT 状态 → PREOP → SAFEOP → OP
     └─ 启动所有任务 → 运行
```

## 附录 A: 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| FOC 算力不足 | 高 | 分布式协处理器架构，每个 G474 仅 2-3 关节 |
| 主协同步延迟 | 中 | SPI DMA + 硬件触发，目标 < 50μs |
| EtherCAT 实时性 | 中 | SOEM 软件栈 + ETH DMA，实测 1ms 稳定 |
| 触觉数据量大 | 低 | 指尖本地预处理，仅上传特征值 |
| 功耗过高 | 中 | 协处理器空闲时进入 STOP 模式 |
| PCB 布线复杂 | 中 | 主控 + 协处理器分板设计，FPC 连接 |
