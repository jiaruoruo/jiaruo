## 一、WHY — 为什么做？（机会与价值分析）

### 1.1 核心定义：MCU-less 是 EEA 进化的"最后一公里"

传统 ECU → ZCU（区域控制单元）已是当前主流，但 ZCU 本身仍含独立 MCU。  
**MCU-less = 彻底去除边缘节点 MCU，控制逻辑全部上移至 ZCU/CCU**。

三代 EEA 架构演进对比：

| 指标 | EEA 2.0 分布式（痛点基准） | EEA 3.0 ZCU（当前主流） | EEA 3.x MCU-less（目标态） |
|------|--------------------------|------------------------|--------------------------|
| ECU/节点数 | 50–100 个 | 30–50 个 | 50–80 个 RCP 节点（无 MCU） |
| OTA 节点数 | 50–100 | 30–50 | **仅 4–8 个 ZCU/CCU** |
| 线束总长 | ~2 km | ~1.4 km | **~0.8 km（减 60%）** |
| 边缘固件数量 | 50–100 套 | 30–50 套 | **0（零固件）** |
| 新功能 TTM | 12–24 个月 | 8–15 个月 | **3–6 个月** |
| 整车 BOM 节省 | 基准 | −15% | **−30%（对比 2.0）** |

### 1.3 看客户

#### 1.3.1 汽车领域客户

**目标用户画像**：
- 用户类型：主流整车 OEM（吉利/长安/理想/小鹏等）及其 Tier1 供应商（安波福/博世/大陆等）
- 规模：年产量 10 万辆以上的量产平台；2026–2028 新平台立项阶段的架构决策团队
- 核心使用场景：车身域控制器（门锁/座椅/氛围灯/天窗/雨刮），ASIL-B 以下节点

**核心痛点（Top 3）**：
1. **OTA 维护成本极高**：整车 OTA 涉及 50–100 个边缘节点固件，任一节点刷写失败都可能影响交车；固件版本管理混乱导致召回风险持续存在
2. **线束重量与成本**：点对点布线导致线束总长 1500–2000m；新能源车每减重 1kg 可提升续航约 0.3%，但传统架构减重空间极小
3. **SDV 战略受阻**：新功能开发周期 12–24 个月，每次功能迭代需硬件改版 + RTOS/固件重开发 + 功能安全重认证

**MCU-less 对 SDV 核心诉求的支撑**：

| SDV 核心诉求 | MCU-less 如何支撑 |
|------------|----------------|
| OTA 功能迭代 | 边缘零固件 → OTA 复杂度从"整车百节点"降至"ZCU/CCU 数节点" |
| 功能按需订阅 | ZCU 侧软件控制 → 同一硬件平台可动态激活不同功能 |
| 软硬件解耦 | RCP 芯片标准化 → 更换 ZCU 软件不影响边缘硬件，反之亦然 |
| 快速迭代 | 边缘无软件 → 新功能仅需 ZCU 侧软件升级，无需重新认证边缘固件 |

**功能安全适用边界（客户最关心的红线）**：

| 应用域 | MCU-less 适用性 | 原因 |
|-------|---------------|------|
| 车身域（门锁/座椅/照明/雨刮） | ✅ **强烈推荐** | 控制逻辑简单，无本地安全计算需求 |
| 智能电源域 | ✅ 推荐 | 电源路由逻辑可由硬件承担 |
| 热管理系统 | ✅ 可用 | 多执行器协调，逻辑可上移 |
| 底盘气悬域 | ⚠️ 不推荐 | 本地控制算法复杂，域控 CPU +10% 负载 |
| 制动/转向/气囊（ASIL-D） | ❌ **严格禁止** | 必须本地降级（Fallback），MCU 不可去除 |

> **结论**：MCU-less 的适用范围是**车身舒适域（Body Domain）**，ASIL-B 以下场景。ASIL-D 功能安全系统必须保留本地 MCU 作为降级保障。

#### 1.3.2 机器人领域客户

**目标用户画像**：
- 用户类型：人形机器人整机厂（宇树/优必选/小米机器人/特斯拉机器人等）及关节模组供应商
- 规模：追求 ¥99,999 量产价格目标的整机厂；外设节点密度 >30 个的商用机型（如 UBTECH Walker X 的 200+ 节点）
- 核心使用场景：
  - **立即可落地**：皮肤触觉传感器阵列（32–128 路 IO）、LED 状态灯、散热风扇群、夹爪末端执行器
  - **中期落地**：关节模组电机控制（2027–2028 拐点后）

**核心痛点（Top 3）**：
1. **固件碎片化，TTM 极长**：关节模组每颗 MCU + FOC 固件需独立开发维护，30–50 套固件碎片化，OTA 需逐一刷写，新算法 TTM 达 6–12 个月
2. **小型化瓶颈**：关节控制板 PCB 30×40mm，每个手指关节 MCU + 驱动芯片体积超过关节可用空间（<10mm×15mm），是灵巧手小型化的直接障碍
3. **线束重量制约负载能力**：臂部 7 个关节每关节需 8–14 根线缆穿越折弯处，整机线束 1.5–2 kg；每降 100g 可提升末端负载能力约 10%

**机器人外设节点 MCU-less 机会（立即可落地，无技术风险）**：

| 外设节点类型 | 当前方案 | MCU-less 替代方案 | 收益 |
|------------|---------|----------------|-----|
| **皮肤/触觉传感器阵列** | 多个分布式 MCU 采集 + CAN 上传 | RCP 节点直接转发 ADC/GPIO 数据 | PCB 减小 50%+，重量降低 |
| **状态 LED / 显示条** | MCU + SPI 控制 LED 驱动 | RCP 节点直接控制 LED Driver | 零固件，OTA 复杂度归零 |
| **散热风扇/泵** | MCU PWM + 转速反馈 | RCP 节点 PWM + 硬件测速 | 响应更快（硬件状态机 μs 级） |
| **末端执行器（夹爪）** | MCU + 力传感器 + 电机驱动 | 专用夹爪控制 ASIC + RCP 接口 | 夹爪模块标准化互换 |
| **电池管理子模块** | MCU + AFE 芯片 | ASIC + 10BASE-T1S 上报 | 安全可靠性提升 |
| **摄像头电源/使能** | MCU GPIO 控制 | RCP 芯片直接输出 | 节省独立 MCU |

### 1.5 看自己

**✅ 优势（以国内 Tier1/整机厂视角）**：
- **优势 1**：本土协同优势——与汇顶 GE1101 等国产芯片处于同一生态圈，联合开发响应速度快于国际 Tier1
- **优势 2**：架构迁移能力——已具备 ZCU SOA 服务化开发经验（参考小鹏 XEEA3.5 的 300+ 原子化服务理念）
- **优势 3**：双赛道覆盖——汽车车身域 + 机器人外设节点底层技术高度共通，一套能力体系同时覆盖两个市场
- **优势 4**：成本优势——汇顶 GE1101（~14 RMB）IO 密度（120 路 vs 12 路）比 ADI AD3304（~$1.3）优势显著
- **优势 5**：汽车→机器人迁移路径已验证——小米 YU7（线束减少 40%）→ 机器人团队直接复用；小鹏 XEEA3.5（线束减重 30%）→ 小鹏鹏行机器人沿用 10BASE-T1S 规划

**⚠️ 短板**：
- **短板 1**：RCP 中间件能力薄弱——嵌入式固件团队尚未向"服务化软件工程师"转型
- **短板 2**：功能安全认证路径不清晰——ASIL-B 认证工具链缺失；认证边界迁移工程成本高
- **短板 3**：机器人专用验证不足——100BASE-T1 在关节动态弯折/振动环境（每天 10,000–100,000 次）下的可靠性尚无专项数据
- **短板 4**：10BASE-T1S 工具链不成熟——调试工具链（示波器/协议分析仪）不完善，客户导入摩擦大

#### 1.6.2 机器人领域机会（重点补充）

**① GPAN 替代 EtherCAT 的机会点深度分析**

EtherCAT 是当前机器人关节通信的事实标准，但其硬件成本高、软件栈复杂、每关节独立走线带来显著成本与重量负担。GPAN（100BASE-T1 + RCP）为"末端总线"层提供了更低成本的替代路径。

**硬件成本对比（单关节模组）**：

| 硬件成本项 | EtherCAT 方案 | GPAN / MCU-less 方案 | 节省金额 |
|----------|-------------|-------------------|---------|
| 通信芯片（Slave/RCP） | EtherCAT Slave ASIC ¥20–50 | GE1101 RCP 芯片 **~¥14** | ¥6–36 |
| 关节 MCU（Cortex-M4/M7） | ¥15–30（每关节独立 MCU） | **¥0**（硬件状态机，无 MCU） | ¥15–30 |
| 晶振 + 复位 + 去耦电路 | ¥3–8 | **¥0**（RCP 芯片内置时钟） | ¥3–8 |
| Flash / EEPROM（程序存储） | ¥5–15 | **¥0**（无固件） | ¥5–15 |
| PCB 制造（层数 / 面积） | 30×40 mm，4–6 层，¥20–50 | **15×20 mm，2–4 层，¥10–25**（缩减 56%） | ¥10–25 |
| 关节走线（每关节单独线对） | 2–4 对线缆穿越折弯处，¥5–15/关节 | **100BASE-T1 单对总线串联，¥1–3/关节** | ¥4–12 |
| 接插件（每关节独立连接器） | 8–14 针接插件 × 关节数，¥3–8 | 总线菊花链，接插件减少 70%，**¥1–2** | ¥2–6 |
| **单关节硬件 BOM 合计** | **¥71–176** | **¥26–44** | **¥45–132（节省约 50–60%）** |

> 📊 **整机（30 关节）硬件节省估算**：¥45–132 × 30 = **¥1,350–3,960 元/台**（约占整机 BOM 的 5–15%）

**软件及开发成本对比**：

| 软件成本项 | EtherCAT 方案 | GPAN / MCU-less 方案 | 节省估算 |
|----------|-------------|-------------------|---------|
| 主站协议栈授权 | 商用授权 ¥3,000–2 万/台 | RCP 协议栈开源（IEEE TC18 草案），**无授权费** | ¥3,000–2 万/台 |
| 从站固件开发（每关节 FOC 固件） | 每关节独立固件 ≈ 3–6 人月；30 关节 ≈ **15–30 人月** | **零固件**；ZCU 侧服务化开发 ≈ 3–5 人月 | **约 12–27 人月（节省 80%+）** |
| OTA 刷写维护（每次迭代） | 30–50 个固件节点逐一刷写；OTA 失败风险高（砖机需返厂） | **仅 4–5 个肢体控制器** OTA；关节层零固件，OTA 失败风险归零 | 单次 OTA 工程成本降低 70%+ |
| 功能安全认证 | 每个关节从站需单独认证（认证文档 × 30–50 节点） | **仅肢体控制器层统一认证**；认证边界大幅收窄 | 认证成本降低 60%+ |
| **软件总成本（30 关节整机项目）** | **¥150–300 万** | **¥30–60 万** | **节省 ¥120–240 万/项目** |

**功能与性能维度对比**：

| 性能维度 | EtherCAT | GPAN 100BASE-T1 + RCP | 差距分析 |
|---------|---------|---------------------|---------|
| 通信速率 | 100 Mbps（全双工） | **100 Mbps（全双工）** | 持平 ✅ |
| 电流环延迟（10–50 μs） | ✅ EtherCAT 可满足（DC 同步，抖动 <1 μs） | ⚠️ 需专用电机 ASIC 硬件实现；100BASE-T1 总线延迟约 50 μs，不满足 10 μs 要求 | **EtherCAT 领先（电流环暂不可替代）** |
| 速度环延迟（100–500 μs） | ✅ 可满足（DC 时钟同步，典型 250 μs） | ⚠️ 需 PLCA 调度严格验证 | EtherCAT 稍有优势 |
| 位置环延迟（1–4 ms） | ✅ 充分满足 | ✅ **100BASE-T1 + RCP 完全可满足**（典型延迟 ~50 μs，远优于 1 ms 要求） | 持平 ✅ |
| 外设控制（10–100 ms） | ✅ 可满足（过设计，成本高） | ✅ **完全满足，成本远低**（GE1101 单芯片管理 120 路 IO） | **GPAN 优势显著** ✅ |
| 节点 IO 密度 | EtherCAT Slave 本身无直接 IO（需外接 MCU + 驱动芯片） | **GE1101 单芯片 120 路 IO**，可直接驱动执行器 | **GPAN 显著优势** ✅ |
| 线束数量 | 每关节独立线对：臂部 7 关节 = 14 对走线 | **单对总线串联**：7 关节共用 1 对总线（减少 85%） | **GPAN 显著优势** ✅ |
| 生态成熟度 | ✅ 成熟（工业标准 20 年，Beckhoff/Omron/Panasonic 全线支持） | 🔄 新兴（GE1101 2026Q3 样品，RCP 标准草案阶段） | **EtherCAT 显著领先** |
| 调试工具链 | ✅ 完善（Wireshark 插件、TwinCAT 诊断、JTAG 调试） | ⚠️ 不完善（100BASE-T1 协议分析仪稀缺，无 JTAG 调试口） | EtherCAT 领先 |
| 标准开放性 | ETG 专有标准，Beckhoff 主导 | **IEEE 802.3bw 开放标准**；RCP 由 IEEE TC18 主导（草案） | **GPAN 路线更开放** |

**适用场景矩阵（替代建议）**：

| 关节类型 / 控制层 | EtherCAT 保留 | GPAN / MCU-less 替代 | 时间节点 |
|----------------|-------------|-------------------|---------|
| 大关节电流环（10–50 μs） | ✅ **保留**（实时性不可替代） | ❌ 当前不可替代（等待专用 FOC ASIC） | 2027–2028 |
| 大关节速度环（100–500 μs） | ✅ **保留**（PLCA 验证未充分） | ⚠️ 过渡期混合架构 | 2026–2027 |
| 关节位置环外环（1–4 ms） | 可替代 | ✅ **立即可用（Phase 2）** | 2026–2027 |
| **灵巧手全部关节（12 路）** | EtherCAT 过设计，成本极高 | ✅ **1 片 GE1101 覆盖整只手**（120 路 IO，零固件） | **立即可落地** |
| **外设节点（皮肤/LED/散热/夹爪）** | EtherCAT 过设计，完全不适合 | ✅ **强烈推荐 GPAN**（成本低 50%+，IO 密度高 10 倍） | **立即可落地** |

> **核心结论**：EtherCAT 在电流环实时性（10–50 μs）和生态成熟度上具有不可替代的优势，但在**外设节点**和**灵巧手控制**场景中，GPAN / MCU-less 以**低 50–60% 的硬件成本**、**少 80% 的固件工作量**、**少 85% 的走线数量**形成压倒性优势。  
> **机器人整机厂最优策略：大关节电流/速度环保留 EtherCAT，外设节点和灵巧手立即迁移 GPAN**，双总线并行直至专用 FOC ASIC 成熟后逐步全面替代。

**② 机器人领域机会总表**：

| 机会点 | 机会描述 | 预估价值 | 可行性 |
|-------|---------|---------|-------|
| **机器人外设节点 MCU-less** | 皮肤传感器/LED/散热/夹爪等外设节点，技术风险低 | 每台整机外设节点节省 ¥500–1,000；固件开发成本归零；节点 PCB 缩小 50%+ | ✅ **高**（立即可落地；无需等待专用 ASIC） |
| **机器人关节 MCU-less 中期布局** | 手指/腕关节位置环（慢环）MCU-less 化；大关节速度环等待专用 ASIC | 每台整机 30 关节节省 ¥2,000–3,900；PCB 缩减 56%；关节直径可减 2–4mm | 🟡 **中**（手指/腕关节 2026–2027 可行；大关节 2027–2028 依赖专用电机 ASIC） |
| **灵巧手场景** | 1 片 GE1101 覆盖整只手（12 路手指关节控制，120 路 IO，PCB 可做至 8×12mm）；突破手指关节空间瓶颈 | 灵巧手 MCU 从 12 颗降至 1 颗（↓92%）；OTA 节点减少 85%+ | ✅ **高**（GE1101 已有 POC 验证；是最具差异化的机器人应用场景） |

### 1.7 第一章总结

- **结论 1**：MCU-less 技术已完成从概念到量产的跨越（宝马 2024），进入规模化复制阶段，**2026–2028 是关键窗口**，入场越早技术壁垒越厚。
- **结论 2**：汽车与机器人双赛道的底层技术高度共通（100BASE-T1 + RCP + SOA），**一套能力体系可同时覆盖两个市场**，投入产出比高。
- **结论 3**：100BASE-T1（GE1101）路线在 IO 密度、速率、延迟上对 10BASE-T1S（ADI）具有显著优势，是国内市场的差异化切入点；但量产稳定性和 AEC-Q100 认证仍是最大不确定性。
- **战略意义**：谁先建立起 **100BASE-T1 + RCP 中间件 + 功能安全认证（ASIL-B）** 的完整能力体系，谁就能在 2026–2028 的行业规模化窗口中占据 Tier1 卡位优势，实现从"ECU 模块供应商"到**"软件定义硬件解决方案商"**的战略升级。

## 二、WHAT — 做什么？（技术方案）

### 2.1 双重解耦是 MCU-less 的核心价值

```
[软硬解耦] 硬件标准化 + 功能软件化 → 支持 OTA 升级而无需硬件改版
[软软解耦] 应用逻辑 ⊥ 通信协议栈 → 微服务化，通过标准接口调用边缘 IO
```

**硬件革新本质**：
- 传统 ECU 节点 = `MCU + 晶振 + Flash + 电源管理 + 收发器 + 驱动芯片`
- MCU-less 节点 = `RCP 芯片（含 MAC-PHY + 硬件状态机）+ 驱动芯片`

### 2.2 汽车 EEA 演进路径（三层架构）

**ZCU SOA 软件架构五层模型**（MCU-less 使能的服务链路）：

| 层级 | 角色 | 关键特征 |
|------|------|---------|
| **云端** | 功能仓库 + OTA 管理 | Feature Store 支持按需下发/订阅功能 |
| **CCU** | SOA 服务总线主机 | SOME/IP 或 DDS，服务注册/发现/调用 |
| **ZCU** | 服务代理 + 执行节点 | 5 层软件栈，承担本区域全部控制逻辑 |
| **MCU-less 节点** | 纯硬件 IO 执行器 | 零 OS，零固件，仅响应 RCP 命令帧 |

### 2.3 机器人 EEA 演进路径收益

两代机器人 EE 架构关键指标收益：

| 指标 | 传统 EE 架构 | MCU-less 架构 | 改善幅度 |
|------|------------|--------------|---------|
| 关节模组 MCU 数量 | 30–50 颗 | **0（ASIC 硬件状态机）** | ↓ 100% |
| 固件套数（关节层） | 30–50 套 | **0** | ↓ 100% |
| OTA 刷写节点数 | 30–50 个 | **4–5 个（仅肢体控制器）** | ↓ 85–90% |
| 穿越关节线缆数 | 8–14 根/关节 | **2–4 根/关节** | ↓ 70% |
| 关节控制 PCB 面积 | 30×40 mm | **15×20 mm** | ↓ 56% |
| 控制板单重 | 15–25 g | **6–12 g** | ↓ 40–50% |
| 整机线束重量 | 1.5–2 kg | **0.5–0.8 kg** | ↓ 50–60% |
| 整机 BOM 节省 | 基准 | **¥2,000–3,900/台** | 约 2–8% 整机成本 |
| 灵巧手 MCU 数量 | 12 颗（每指 1 颗） | **1 颗 GE1101** | ↓ 92% |
| 新算法 TTM | 12–18 个月 | **2–4 个月** | ↓ 70% |

## 三、HOW — 怎么做？（执行策略）

### 3.1 四阶段路线图

| 阶段 | 时间 | 里程碑 | 交付物 |
|------|------|-------|-------|
| **Phase 1** 车灯/氛围照明先行 | 2024–2025 | 宝马 ADI E2B 量产；技术可行性验证 | AD3304/GE1101 双芯片参考设计板；ZCU RCP 中间件 Demo |
| **Phase 2** 车身域全面铺开 | 2026–2027 | 汇顶 GE1101 量产（2026Q3）；主流 OEM 新平台采用；机器人外设节点商业化 | 通过 ASIL-B 认证的 MCU-less 节点模组；机器人外设节点参考设计 |
| **Phase 3** 跨域扩展 | 2027–2028 | 热管理/电源域扩展；机器人手指/腕关节位置环 MCU-less | 机器人关节 MCU-less Gen1 模组 |
| **Phase 4** 软件完全解耦 | 2028–2030 | 整车功能原子化；机器人全关节 MCU-less（依赖专用 ASIC 成熟） | 标准化 RCP 节点平台 + ZCU 服务总线完整方案 |

### 3.2 分角色核心行动建议

**OEM（整车厂）**：
- 🔴 **立即**：在 2026–2027 新平台车身域中原生规划 MCU-less 节点，禁止再新增传统 ECU
- 🔴 **立即**：组建 ZCU 软件平台团队，建立 SOA 原子服务库
- 🟡 **中期**：制定整车分域 MCU-less 路线图，明确各域 ASIL 等级边界

**Tier1（零部件供应商）**：
- 🔴 **立即**：建立 MCU-less 节点参考设计平台（含 AD3304/GE1101 双方案）
- 🔴 **立即**：培养 RCP 中间件与 ZCU SOA 服务开发能力；固件工程师向"服务化软件工程师"转型
- 🟢 **长期**：向"软件定义硬件"转型，从卖 ECU 模块转向提供"RCP 节点 + ZCU 服务包"软硬一体解决方案

**机器人整机厂**：
- 🔴 **立即**：在外设节点（皮肤传感器/LED/散热风扇/夹爪）中立即引入 MCU-less 方案
- 🔴 **立即**：建立机器人主计算机→肢控→关节同构映射，将外设控制逻辑集中到肢控 ZCU
- 🟡 **中期**：联合芯片厂商定制**机器人专用 MCU-less 电机控制 ASIC 规格**（FOC + 100BASE-T1 + RCP 一体化）

### 3.3 最大风险预警

**⚠️ 最大风险：RCP 协议标准碎片化（高概率 + 高影响）**

应对措施：
1. **立即建立 ADI/汇顶双协议栈验证能力**，保持协议抽象层兼容两套实现，防止客户锁定
2. **派员参与 IEEE TC18 标准工作组**，争取在标准制定阶段影响方向
3. **在客户合同中明确 RCP 版本兼容性条款**，防止被单一厂商锁定
4. **汇顶 GE1101 量产时间节点（2026Q3）是 Phase 2 的关键门控条件**，如延迟超过 1 个季度需立即启动 ADI AD3304 替代方案

其他主要风险：

| 风险类型 | 风险描述 | 概率 | 影响 | 应对策略 |
|---------|---------|------|------|---------|
| 技术风险 | 汇顶 GE1101 量产延迟，AEC-Q100 认证周期不确定 | 中 | 高 | Phase 1 先以 AD3304 完成 POC；GE1101 作为升级路径，预留 1 个季度缓冲 |
| 技术风险 | 机器人关节电流环实时性（10–50μs）10BASE-T1S 总线无法满足 | 高 | 中 | Phase 1–2 聚焦外设节点和位置环；大关节电流环等待专用 ASIC（2027–2028） |
| 技术风险 | 100BASE-T1 柔性 PCB 在关节动态弯折环境（每天 10,000–100,000 次）可靠性未验证 | 中 | 高 | Phase 2 启动机器人关节动态弯折测试台专项验证 |
| 市场风险 | CAN FD Light 在低成本车灯等场景成本优势显著（几毛钱 vs 10+ 元） | 高 | 中 | 明确双轨策略：100BASE-T1 适用高价值/高 IO 节点，CAN FD Light 适用超低成本节点 |

## 四、最终战略结论

> **MCU-less 技术在汽车和机器人两大领域代表了一次从"分散固件"到"集中服务"的架构范式转变。**
>
> - **车载领域是今天的主战场**：技术可行性已验证，商业逻辑已跑通，2026–2028 年是关键规模化窗口
> - **机器人领域是明天的最大增量市场**：外设节点已具备立即落地条件，关节模组的完整 MCU-less 化依赖专用 ASIC 的诞生，预计 2027–2028 年迎来拐点
> - **最优资源配置策略**：**现在布局外设节点的低风险突破口，同时储备关节模组的技术能力**，是未来 3–5 年最优的资源配置策略

### 两大领域对比速查

| 对比维度 | 车载应用 | 机器人应用 |
|---------|---------|---------|
| **成熟度** | 已量产（宝马 ADI E2B，2024） | 外设节点可用；关节模组预研阶段 |
| **单台价值收益** | ¥476–1,200/车 | ¥2,000–3,900/台（外设+关节合计） |
| **价值密度（占整机成本）** | ~0.3–0.6%（20 万元车） | **~2–8%**（5–10 万元机器人） |
| **最快落地域** | 车身舒适域（门锁/座椅/灯光） | 外设节点（皮肤传感/LED/散热） |
| **功能安全要求** | ASIL-B 适用；ASIL-D 禁用 | ISO 13849 PLd/PLe 约束关键关节 |
| **线束/重量收益** | 减重 10–15 kg/车，续航提升 1–2% | 减重 1–2 kg/台，末端负载能力提升 ~5% |
| **关键催化剂** | 汇顶 GE1101 量产（2026Q3）；RCP 标准发布 | 机器人专用 MCU-less 电机 ASIC 诞生（2027–2028） |
