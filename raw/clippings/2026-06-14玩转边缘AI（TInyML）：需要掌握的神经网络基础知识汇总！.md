# 玩转边缘AI（TInyML）：需要掌握的神经网络基础知识汇总！

## 文章简介

很多嵌入式工程师开始接触 AI 时，最容易走偏的地方，不是代码，而是神经网络基础没真正建立起来。表面上会调用训练脚本、会导出 `.tflite`，但一问模型为什么这么设计、输入输出到底代表什么、为什么量化后精度会掉，就说不清楚。

做嵌入式 AI，不需要一开始就去研究很深的数学推导，但有几类神经网络知识必须真正掌握。因为这些知识会直接决定你能不能看懂模型结构、能不能判断模型是否适合 MCU、能不能定位训练和部署中的问题。

下面不讲空泛概念，直接讲最重要、最常用、最应该掌握的内容。

## 一、先把输入、输出、张量、形状彻底搞清楚

### 1. 样本、特征、标签到底是什么

神经网络本质上是在学习“输入和输出之间的映射关系”。所以第一步，不是先看层数，而是先搞清楚输入和输出分别是什么。

-   **样本**
    
    ：一条可以拿来训练或推理的数据
    
-   **特征**
    
    ：模型真正看到的输入值
    
-   **标签**
    
    ：训练时希望模型输出的标准答案
    

例如动作识别中，一条样本可以是“连续 128 个时刻的三轴加速度数据”；特征就是这 128×3 个数字；标签可能是“走路、跑步、静止”中的某一类。

```
<span leaf=""># 一个动作识别样本的概念示意</span><span leaf=""><br></span><span leaf="">sample.shape = (128, 3)</span><span leaf=""><br></span><span leaf=""><br></span><span leaf=""># 128 表示时间步</span><span leaf=""><br></span><span leaf=""># 3 表示 ax, ay, az 三个通道</span><span leaf=""><br></span><span leaf=""><br></span><span leaf="">label = 1 &nbsp; # 例如 0=静止, 1=走路, 2=跑步</span>
```

如果这一步没搞清楚，后面训练、量化、部署都会错。因为模型不是在学习“抽象概念”，而是在学习这堆数字和目标之间的关系。

### 2. 什么是张量，为什么要关注 shape

张量可以先简单理解成“带形状信息的多维数组”。嵌入式工程师可以先不用把它想得太复杂，本质上就是数据加说明书。

最需要关注的是 `shape`，也就是数据形状。因为 shape 一错，模型立刻无法正常工作。

```
<span leaf=""># 常见输入例子</span><span leaf=""><br></span><span leaf=""><br></span><span leaf="">(1, 128) &nbsp; &nbsp; &nbsp; &nbsp;# 单条一维序列</span><span leaf=""><br></span><span leaf="">(1, 128, 3) &nbsp; &nbsp; # 单条时间序列，多通道输入</span><span leaf=""><br></span><span leaf="">(1, 32, 32, 1) &nbsp;# 单张灰度图</span><span leaf=""><br></span><span leaf="">(1, 40) &nbsp; &nbsp; &nbsp; &nbsp; # 单条提取后的特征向量</span>
```

这里的第一个维度 `1` 常常表示 batch size，也就是一次送进去几条样本。部署到 MCU 上时，通常就是一次处理一条，所以常见是 1。

**最容易犯的错误：**训练时输入是 `(128, 3)`，部署时却按 `(3, 128)` 去填数据；训练时做了归一化，部署时直接送原始值；训练时输入是 float，部署时却按 int8 生塞进去。

### 3. 输入到输出的数据流

原始数据预处理神经网络输出分数结果ADC / IMU / Mic / 图像归一化 / 滤波 / 滑窗 / 特征层间运算概率或回归值类别 / 数值 / 告警

## 二、神经元、权重、偏置、激活函数，这几个概念必须真正会用

### 1. 一个神经元到底在做什么

把神经网络拆到最小，你会发现每个神经元做的事情很简单：先做加权求和，再加偏置，最后过一个激活函数。

```
<span leaf="">y = activation(w1*x1 + w2*x2 + ... + wn*xn + b)</span>
```

这里：

-   `x1, x2 ...`
    
     是输入
    
-   `w1, w2 ...`
    
     是权重
    
-   `b`
    
     是偏置
    
-   `activation()`
    
     是激活函数
    

你可以把权重理解成“每个输入有多重要”，把偏置理解成“整体往哪个方向再推一把”。

### 2. 权重和偏置为什么重要

训练神经网络，本质上就是不断调整权重和偏置，让模型输出更接近真实标签。也就是说，训练出来的模型，最后真正被部署到 MCU 上的核心资产，其实就是一堆参数。

```
<span leaf=""># 以一层全连接层为例</span><span leaf=""><br></span><span leaf=""># 输入长度: 10</span><span leaf=""><br></span><span leaf=""># 输出长度: 4</span><span leaf=""><br></span><span leaf=""><br></span><span leaf="">weights.shape = (10, 4)</span><span leaf=""><br></span><span leaf="">bias.shape &nbsp; &nbsp;= (4, )</span><span leaf=""><br></span><span leaf=""><br></span><span leaf=""># 参数个数 = 10*4 + 4 = 44</span>
```

这里你就要立刻建立一个意识：参数个数越多，模型一般越大，占用 Flash 越多，推理时乘加运算也越多。

### 3. 激活函数不是装饰，它决定网络有没有非线性能力

如果没有激活函数，多层全连接堆起来本质上还是线性变换，表达能力很有限。激活函数的作用，就是让模型能拟合更复杂的关系。

| 激活函数 | 形式 | 作用 | 嵌入式AI里怎么看 |
|---------|----------------|------------|-----------|
| ReLU | max(0, x) | 简单、常用、计算量小 | 最常见，部署友好 |
| Sigmoid | 1 / (1 + e^-x) | 输出 0~1 | 常用于二分类输出 |
| Tanh | -1 ~ 1 | 零中心 | 部分时序任务会见到 |
| Softmax | 多分类归一化 | 输出各类别概率 | 多分类输出层常见 |

**非常实用的判断方式：**隐藏层最常见看 ReLU，二分类输出常见看 Sigmoid，多分类输出常见看 Softmax。如果你在 Netron 里看到这些结构，至少应该知道它大概在干什么。

## 三、必须认识的几类网络层：不是所有层都适合嵌入式部署

### 1. 全连接层 Dense：最容易理解，也最容易参数膨胀

全连接层的意思是：上一层每个输入都和下一层每个输出相连。

```
<span leaf=""># 假设输入长度 128，输出长度 64</span><span leaf=""><br></span><span leaf="">参数个数 = 128 * 64 + 64 = 8256</span>
```

它的优点是简单直接，适合做小型分类或回归；缺点是输入一大，参数就会迅速增多。所以在 MCU 上，全连接层可以用，但不能无限堆大。

### 2. 卷积层 Conv：适合局部特征提取

卷积层的核心不是“看上去高级”，而是它用较少参数去提取局部模式。做图像、音频频谱、时序局部模式识别时都很常见。

例如关键词识别里，输入如果是声学特征图，卷积层就可以提取局部时间-频率模式；动作识别里，如果把连续数据组织得合适，一维卷积也常见。

```
<span leaf=""># 粗略理解</span><span leaf=""><br></span><span leaf=""># 全连接：每个输入都连每个输出</span><span leaf=""><br></span><span leaf=""># 卷积：用一个小窗口在输入上滑动提特征</span>
```

对嵌入式来说，卷积层的关键不只是“能不能跑”，还要看卷积核大小、通道数、输出特征图尺寸，否则 RAM 压力会很大。

### 3. 池化层、展平层、归一化层，要知道它们各自干什么

-   **Pooling**
    
    ：压缩特征图尺寸，减少计算量和参数压力
    
-   **Flatten**
    
    ：把多维特征摊平成一维，方便接全连接层
    
-   **Normalization**
    
    ：让训练更稳定，但部署时要注意是否被折叠进模型，还是需要在外部手动做
    

很多部署问题，并不是主干层不会看，而是这些“辅助层”没搞清楚，导致输入输出 shape 对不上。

### 4. 输出层怎么看：分类和回归完全不是一回事

| 任务类型 | 输出含义 | 常见输出层 | 常见结果解释 |
|------|---------|------------------|---------|
| 二分类 | 属于某类的概率 | 1 个神经元 + Sigmoid | 大于阈值判正类 |
| 多分类 | 各类别概率 | N 个神经元 + Softmax | 取最大概率类别 |
| 回归 | 连续数值 | 1 个或多个线性输出 | 直接读数值 |

所以你看到模型最后一层，不能只会说“这是输出层”，而应该能判断：这是分类还是回归，输出值是不是概率，后处理到底应该取最大值还是直接读数。

## 四、训练阶段必须理解的知识：损失函数、反向传播、过拟合、评估指标

### 1. 损失函数：训练就是在不断让损失变小

损失函数不是理论摆设，它就是训练过程中的“误差尺子”。模型每训练一次，都会看看当前输出和真实标签差多少，然后根据这个误差去调整参数。

| 任务 | 常见损失函数 | 你至少要知道什么 |
|-----|------------------------------------------------|--------------|
| 回归 | MSE / MAE | 预测值和真实值差多少 |
| 二分类 | Binary Cross Entropy | 预测概率和标签差多少 |
| 多分类 | Categorical / Sparse Categorical Cross Entropy | 类别分布和真实类别差多少 |

### 2. 反向传播不用会推公式，但必须知道它在干什么

反向传播的本质，就是把输出误差一层一层往前传，然后告诉每个参数该往哪个方向调，调多少。你可以先不推导梯度公式，但必须知道：训练阶段和推理阶段是两件完全不同的事。

-   **训练**
    
    ：前向计算 + 误差计算 + 反向传播 + 参数更新
    
-   **推理**
    
    ：只有前向计算
    

这也是为什么 MCU 上通常只做推理，不做训练。训练太耗算力、太耗内存、太耗时间。

### 3. 过拟合、欠拟合，一定要会判断

嵌入式AI里，很多人只盯着训练集准确率，这是不够的。你要看训练集和验证集的表现是否一致。

-   **欠拟合**
    
    ：训练集都学不好，模型太弱、训练不够或特征不行
    
-   **过拟合**
    
    ：训练集很好，验证集差，说明模型记住了训练数据，但泛化能力差
    

```
<span leaf=""># 一个典型过拟合现象</span><span leaf=""><br></span><span leaf="">epoch 1: train_acc = 0.72, val_acc = 0.69</span><span leaf=""><br></span><span leaf="">epoch 10: train_acc = 0.96, val_acc = 0.75</span><span leaf=""><br></span><span leaf="">epoch 20: train_acc = 0.99, val_acc = 0.71</span>
```

如果出现这种情况，继续训练往往没有意义，应该去检查数据量、数据分布、模型大小、正则化、数据增强这些问题。

### 4. 评估指标不能只看 accuracy

尤其是异常检测、故障识别这类任务，只看准确率很容易误判。

| 指标 | 含义 | 什么时候重要 |
|-----------|---------------|-----------|
| Accuracy | 整体预测对了多少 | 类别均衡时可参考 |
| Precision | 报为正类的里面有多少真的对 | 误报成本高时重要 |
| Recall | 真实正类里抓到了多少 | 漏报成本高时重要 |
| F1-score | 精确率和召回率的平衡 | 类别不均衡时很常看 |

**非常实用的一句话：**如果你的任务里“漏掉异常”比“多报几个异常”更严重，那你就不能只盯准确率，要重点看召回率。

## 五、嵌入式AI特有的神经网络知识：量化、模型大小、运算量、部署约束

### 1. 为什么同一个模型，放到 MCU 上就不一样了

在 PC 上训练时，你可能默认用的是 float32。每个参数 4 字节，算起来方便，精度也高。但一到 MCU 上，Flash、RAM、算力都很紧，所以常见做法是量化成 int8。

| 类型 | 每个参数字节数 | 特点 |
|---------|---------|-----------------|
| float32 | 4 | 精度高，但占空间大 |
| float16 | 2 | 更小，但 MCU 上不一定最优 |
| int8 | 1 | 嵌入式部署最常见 |

如果一个模型有 20,000 个参数：

```
<span leaf="">float32 大小约 = 20000 * 4 = 80000 字节 ≈ 78 KB</span><span leaf=""><br></span><span leaf="">int8 &nbsp; &nbsp;大小约 = 20000 * 1 = 20000 字节 ≈ 19.5 KB</span>
```

差距非常直接。所以做嵌入式AI，必须具备“看到模型结构就开始估算资源”的习惯。

### 2. 量化后为什么精度可能下降

量化的本质，是用更低精度的整数去近似原来的浮点数。近似就一定会带来误差。

```
<span leaf="">real_value ≈ scale * (quantized_value - zero_point)</span>
```

你至少要知道三个点：

-   量化是为了减小模型体积、降低带宽、加快推理
    
-   量化后精度可能下降，尤其是分布复杂或范围变化大的数据
    
-   如果训练后量化效果不好，可以考虑量化感知训练
    

### 3. 不能只看模型大小，还要看中间层内存和运算量

很多人以为模型能塞进 Flash 就能跑，这是不对的。除了参数本身，推理时还有中间激活值、输入输出缓冲区、运行时工作区。

所以做嵌入式部署时，至少要同时看四件事：

-   **参数量**
    
    ：决定模型文件大概多大
    
-   **激活内存**
    
    ：决定 RAM 压力
    
-   **MAC 数量**
    
    ：决定计算负担和推理速度
    
-   **算子支持**
    
    ：决定框架能不能真正跑起来
    

### 4. 一个最实用的模型判断思路

当你拿到一个神经网络模型，不要先问“这模型先进不先进”，而要先按下面顺序判断：

1.  输入 shape 是什么，实际传感器数据能不能组织成这个格式
    
2.  输出代表什么，部署后该怎么解释
    
3.  层类型有哪些，目标推理框架是否支持
    
4.  参数量和运算量大概多少，MCU 资源够不够
    
5.  是否已经量化，量化精度是否可接受
    
6.  前处理流程能不能在嵌入式端完整复现
    

你如果能按这六步去看模型，已经比只会“跑脚本”的状态强很多了。

## 总结

学习嵌入式AI，神经网络知识不用一开始铺得特别宽，但一定要学得足够扎实。最应该优先掌握的，不是复杂理论，而是下面这些真正会影响部署的核心内容：

-   输入、输出、张量、shape 到底表示什么
    
-   神经元、权重、偏置、激活函数到底在做什么
    
-   Dense、Conv、Pooling、输出层分别起什么作用
    
-   损失函数、反向传播、过拟合、评估指标怎么看
    
-   量化、模型大小、运算量、内存占用怎么影响 MCU 部署
    

把这些真正学明白，你再去看训练脚本、模型结构图、推理代码，很多原来模糊的地方都会变清楚。到那时，你就不是“在调用 AI 工具”，而是真的开始理解神经网络在嵌入式设备上是怎么工作的。
